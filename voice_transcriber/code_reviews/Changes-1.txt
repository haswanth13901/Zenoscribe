Test 1: Soniox clean-close handling
- Updated Voice-transcriber/transcribe.py to treat ConnectionClosedOK as a normal upstream close instead of an error.
- Hardened pump_results/cleanup logic so normal Soniox disconnects do not surface as client errors.

Test 2: Frontend error teardown
- Updated Voice-transcriber/static/index.html so error frames call stop() and fully tear down audio/websocket state.
- Improved stop() to accept a final status and clean up mic/socket resources.

Test 3: Double-start race
- Added a connecting guard in Voice-transcriber/static/index.html.
- Disabled the Start button while connecting to prevent multiple streams / duplicate /ws sessions.

Test 4: Turn buffer race
- Changed Voice-transcriber/transcribe.py takeover logic to hold the lock across buffer carryover and flush.
- Prevented watchdog/flush races that could split, duplicate, or drop turns.

Test 5: Blocking event loop I/O
- Updated Voice-transcriber/transcribe.py to offload DB and file I/O to asyncio.to_thread.
- Added an async audio writer queue so wf.writeframes and wave/db ops do not block the event loop.

Test 6: gather cancellation semantics
- Updated Voice-transcriber/transcribe.py to use explicit tasks with return_exceptions=True.
- Centralized cleanup so one task failure does not incorrectly cancel sibling tasks or make the session appear crashed.

Test 7: WAV close vs cancelled writer
- Ensured the audio writer task is finished before closing the WAV file in Voice-transcriber/transcribe.py.
- Serialized writer teardown to avoid truncated or corrupt WAV files.

Test 8: Failed session history pollution
- Added logic in Voice-transcriber/transcribe.py to discard empty sessions with zero turns.
- Deleted the temporary WAV for empty sessions and skipped DB registration when no audio/turns were captured.

Test 9: Stale Soniox model names
- Updated Voice-transcriber/soniox_client.py to use current Soniox model names: stt-rt-v5 and stt-async-v5.

Test 10: Dynamic API key loading
- Updated Voice-transcriber/soniox_client.py to read SONIOX_API_KEY at runtime through get_api_key().
- Replaced static import-time API key/auth header initialization with get_headers() and rt_config() calls.

Test 11: SpeakerLabeler fallback
- Fixed Voice-transcriber/soniox_client.py so speaker=None falls back to the current speaker label instead of inventing a new user-N slot.
- Preserved last known speaker label for unlabeled tokens.

Test 12: Pending-as-suffix safety
- Reworked Voice-transcriber/transcribe.py to track buffered and pending tokens explicitly instead of assuming pending is a suffix of buf text.
- Prevented silent corruption of turn text on concurrent flush or carryover.

Test 13: Batch poll timeout and cleanup
- Added a timeout to transcribe_file() in Voice-transcriber/soniox_client.py.
- Added cleanup helpers to delete the uploaded remote file and transcription job on completion or failure.

Test 14: Atomic last-admin protection
- Added conditional UPDATE/DELETE logic in Voice-transcriber/db.py for set_active() and delete_user().
- Updated Voice-transcriber/routes_api.py to reject operations when the last active admin would be removed.

Test 15: Remove JWT from WS query string
- Updated Voice-transcriber/static/index.html to open /ws without ?token and send a one-time auth frame.
- Updated Voice-transcriber/transcribe.py and Voice-transcriber/auth.py to authenticate on the first WS message.
- Updated README.md to document that JWTs are not exposed in the URL/query string.

Test 16: Login rate limit
- Added failed_logins tracking in Voice-transcriber/db.py.
- Updated Voice-transcriber/routes_api.py to throttle repeated /api/login failures per username+IP and return 429 after the threshold.

Test 17: Upload size limit
- Added MAX_UPLOAD_SIZE settings in Voice-transcriber/config.py.
- Updated Voice-transcriber/routes_api.py to validate Content-Length and stream the uploaded file in chunks with an enforced size cap.

Test 18: Seed admin password strength
- Added MIN_PASSWORD_LENGTH in Voice-transcriber/auth.py.
- Updated ensure_seed_admin() to reject weak ADMIN_PASSWORD values and generate a secure password instead.
